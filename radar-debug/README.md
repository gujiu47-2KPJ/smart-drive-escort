# 雷达调试工程（觅感 MS60-1211S80M / 隔空 AT6010）

独立的最小 ESP-IDF 工程。按产品手册「图 7 典型应用电路」，**OUT 与 TX/RX 同时连接**，分工是：

- **OUT → 感应数据**（有人/无人），程序用 GPIO 中断读边沿、量脉冲宽度
- **TX/RX → 调参**，程序只做只读诊断（版本 / 感应开关 / 边界值 / 用户配置）

结构和方法与 `imu-debug` 保持一致，符合 PROJECT.md「所有模块必须可独立测试」的原则。

## 目录

```
radar-debug/
```

## 快速开始

用 VS Code 打开 `G:\codex-workspace\radar-debug`，在 ESP-IDF 终端里：

```
idf.py set-target esp32s3
idf.py build
idf.py -p COM编号 flash monitor
```

串口固定 **115200 8N1**。

## 接线

| 雷达引脚 | 接到 ESP32-S3 | 作用 | 程序里的宏 |
|---|---|---|---|
| VCC（接口1.3） | 3V3 | 供电，建议 3.3 V，VCC-GND 间并 10uF + 0.1uF | — |
| GND（接口1.2 / 2.2） | GND | 共地 | — |
| OUT（接口1.1） | **GPIO42** | **数据**：有人时输出有效电平 | `OUT_GPIO` |
| TX（接口2.1） | **GPIO21** | 调参回读 | `RADAR_UART_RX_GPIO` |
| RX（接口2.3） | **GPIO14** | 调参下发 | `RADAR_UART_TX_GPIO` |

引脚是规划值，接线前请确认，改 `main/radar_out_main.c` 顶部四个宏即可。

**OUT 为什么不用 GPIO2**：相机板插上 IMU 后只剩 GPIO1/2/14/21/47，GPIO2 上挂了板载 LED。
雷达的 OUT 要驱动 LED 才能读到高电平，可能被钳在 LED 正向压降附近（约 2 V），
低于 ESP32 的输入高电平门限，读数不可靠。GPIO42 平时空着（只在 JTAG 调试时用），更干净。
如果搬到最小板上，把 `OUT_GPIO` 改成一个空闲脚即可。

**最容易搞反的就是 TX/RX**：ESP32 的 TX 要接雷达的 RX。接反了程序会报"三种波特率都没有应答"。

## 串口输出内容

1. 启动横幅：芯片型号、IDF 版本、UART 端口与引脚、模块供电要求
2. **步骤 1**：初始化 UART + **波特率自动探测**（依次试 921600 / 115200 / 9600）
3. **步骤 2**：软硬件版本号（软件 / 客户 / 硬件三段版本）
4. **步骤 3**：当前配置 —— 感应开关、算法边界值、用户配置（三档距离与灵敏度）
5. **步骤 4**：查询一次检测信息
6. **步骤 5**：连续轮询（默认 200 ms 一次），每帧打印全部字段；每 5 秒打一次统计

单帧输出形如：

```
    12  [查询] type=0(完整检测) detected=1 det=0x05(靠近+运动) 距离=1.234 m 角度=-12° 速度=0(预留) 置信度(距/角)=14/11 帧号=88213
```

统计块包含：轮询次数与实测频率、检测到目标的次数、距离/角度范围、距上次检测的时间、
主动上报帧数，以及链路计数（发命令 / 收回复 / 超时 / 校验错 / 上报丢弃）。

## 协议要点（写驱动时踩过的坑）

- **命令帧校验是 2 字节小端**。例：`58 FE 00 56 01`，因为 0x58+0xFE+0x00 = 0x156，
  低字节 0x56、高字节 0x01。文档正文只写"校验码为前面数据之和"，看示例才确认是 2 字节。
- **主动上报帧 0x5A 是 1 字节校验**，和命令帧不是一套，别混用。
- **只有检测到目标才会上报**，没目标时总线上一片安静。所以"收不到"不等于"模块坏了"，
  程序里必须用超时来判定，不能当成掉线。
- 速度字段 `velo_val` 在协议里标注"目前预留 / todo"，**拿不到有效值**。
  程序照样打印它，但值恒为 0；要做"接近趋势"只能用距离差分（Δ距离/Δt）。
- 模块出厂波特率是 921600，可能被上位机改过，所以调试程序做了自动探测。

## 排错对照

| 现象 | 可能原因 | 怎么办 |
|---|---|---|
| 三种波特率都无应答 | 供电 / 共地 / TX-RX 接反 | 查 VCC 与 GND；把 GPIO14 和 GPIO21 对调试试 |
| 偶尔有应答但校验错多 | 波特率不对、线太长、无屏蔽 | 用厂商上位机确认波特率；缩短杜邦线 |
| 一直 is_detected=0 | 感应功能被关了，或目标不在探测区 | 看第 3 步的"感应功能"；把目标放到雷达正前方 1~3 m |
| 距离数值明显跳变 | 置信度低 | 看 `置信度(距/角)`，距离置信度 <12 时数值不可信 |
| 读取用户配置失败 | 部分算法版本不支持该命令 | 属正常，其余功能不受影响 |

## 与主工程的关系

要并入主固件时，把 `components/radar_at6010/` 整个目录复制到
`G:\codex-workspace\firmware\components\` 即可，对外接口不用改。
注意主固件里雷达用 UART1、IMU 用 I2C0，两者不冲突。
