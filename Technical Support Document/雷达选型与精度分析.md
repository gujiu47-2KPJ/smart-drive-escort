# 雷达精度归因与选型分析

> 汇总日期：2026-10-02
> 适用项目：ESP32-S3 端侧多模态融合主动安全头盔（果园农机防撞预警）
> 现有硬件：觅感 MS60-1211S80M（人存版，AT6010 芯片）

本文汇总对现有雷达的精度归因分析、上位机逆向的价值边界、人存版与 BSD 版的差异，
以及面向预算的选型建议。所有数值均标注来源，未经验证的推测单独标出。

---

## 〇、结论摘要

1. **精度瓶颈不在协议层**。我们的协议实现逐字节正确，已与官方文档核对。
2. **瓶颈在模块内部算法 + 物理环境 + 参数配置**，外部无法通过逆向改善测量精度。
3. **上位机完整逆向不会提高精度**；唯一有价值的逆向目标是 `0x3C` 瞬时功率命令。
4. **人存版与 BSD 版既有无件差异也有固件差异**，且 BSD 对防撞场景未必更优。
5. **选型结论**：补一块便宜的 24GHz 多目标模块（约几十元）补上"多目标+速度"，
   角度分辨率交给已有的摄像头，而不是花钱堆雷达。

## 一、精度归因：瓶颈到底在哪

### 1.1 协议读取层：已排除

**证据 1 —— 字段偏移逐字节吻合。**
官方《AT6010 SOC HCI Protocol V1.0》§3.2.6 定义 0x30 回复结构：

```c
u8  is_detected;
u8  det_result;
u16 range_val;    /* 距离，单位 mm */
s16 angle_val;    /* 角度，单位 1 度 */
s16 velo_val;     /* 速度，文档标注 todo（预留） */
u8  reserved[6];
u8  rb_conf;      /* 综合距离置信度 0~16，<12 时距离可能不准 */
u8  angle_conf;   /* 综合角度置信度 0~16，<8 时角度可能不准 */
u32 frame_idx;
```

驱动实现中 `f[14]=rb_conf`、`f[15]=angle_conf`、`f[16..19]=frame_idx`，位置完全一致。

**证据 2 —— 帧格式与校验已验证。**
上位机 log 中 5 条命令（0x30/0x31/0x32/0x33/0xD0）全部收到合法回复，校验错误为 0。

**证据 3 —— 已读取该命令能提供的全部字段。**
0x30 不返回原始数据，只返回算法结论。

### 1.2 模块内部算法：主要瓶颈

AT6010 是雷达 SOC，FMCW → FFT → CFAR → 跟踪全部在芯片内部完成，
对外只输出最终判定值。**精度天花板由厂商算法决定，外部不可改。**

### 1.3 物理层面：射频能力足够，算法没吃满

理论距离分辨率由带宽决定：

```
ΔR = c / (2B)
人存版 B = 5 GHz  →  3.0 cm
BSD 版 B = 2 GHz  →  7.5 cm
```

实测现象：同一秒内距离在 110~550 mm 之间跳变，角度在 -18°~+48° 之间跳变。

**结论：射频前端有 3 cm 的分辨能力，输出却有几十厘米的抖动——误差来自检测/跟踪算法与门限，不是射频，也不是我们的读取方式。**

### 1.4 天线架构：测角是先天短板

人存版为 **1T2R**，即只有 2 个接收天线、1 条空间基线。
瑞利角分辨率：

```
Δθ ≈ λ / (N · d · cosθ)
```

阵元间距取 λ/2、N=2 时，正前方（θ=0）：

```
Δθ ≈ 1 rad ≈ 57°
```

不同架构对比（λ/2 间距、正前方）：

| 架构 | 虚拟通道 | 角分辨率 |
|---|---|---|
| 1T2R（现有模块） | 1 基线 | ~57° |
| 2T2R（LD6004） | 4 | ~29° |
| 3T3R（觅感 24G） | 9 | ~13° |
| 3T4R（TI IWR6843） | 12 | ~10° |

**注意区分"精度"与"分辨率"**：精度靠信噪比（相位比较法的单目标测角精度可远优于瑞利限），
分辨率靠物理孔径。角度差在几十度以内的两个目标会被合并。

### 1.5 参数配置：唯一可自由调节的环节

用户观察到的三个现象，全部可由物理与安装解释，且大部分可调：

| 现象 | 原因 | 对策 |
|---|---|---|
| 检测面贴桌面 → 报"呼吸" | 桌面在近场形成大反射面，表面微振动被当作呼吸微动 | 设 `0x34` 运动最近距离，把近场挡在盲区内 |
| 放地面上 → 显示 3.x 米 | 地面是巨大反射面，多径导致虚假距离 | 同上；改进安装方式 |
| 朝空地 → 报"运动" | 灵敏度档过高 + 检测窗口未限制 | `0x35` 调灵敏度（数值越大越不灵敏）；`0xD2` 限最远距离 |
| 几乎没有"无目标"帧 | 门限太宽松 | 同上 |

产品手册《注意事项》相关原文：

> 3) 尽量避免将雷达模块天线正对大型金属设备或管道等，避免产生误报。
> 2) 在雷达 FOV 覆盖范围内天线辐射区域需要良好的净空区域，避免有金属材质的外壳或支架部件。

另有：检测盲区 **0.1 m**；探测范围自天线面起呈**水滴状**分布，偏离法线方向有效距离下降。

### 1.6 尚未利用的信息：置信度

模块会主动告知"本帧是否可信"（`rb_conf` / `angle_conf`），
**当前应用逻辑完全忽略这两个字段**。这是零成本可获得的改进。

> 待确认：实测出现过 `rb_conf = 17`，超出文档标注的 0~16。
> 说明该固件的置信度标度可能与文档不完全一致，建议按"越大越好"的相对量使用。

## 二、上位机逆向的价值边界

### 2.1 结论：不会提高测量精度

官方上位机 `ATRadarSettingTool V1.2` 读取的是同一批 0x30 字段，属于配置 + 显示工具。
继续逆向只能获得命令名与默认参数（已提取完成），不能提升测距/测角精度。

### 2.2 唯一有价值的逆向目标

| 目标 | 可行性 | 说明 |
|---|---|---|
| **`0x3C` 瞬时功率请求** | ✅ 值得一试 | 上位机画波形用，可能返回按距离单元的能量谱；若成立，可自行做峰值检测，在距离维上分离真实目标与地面反射 |
| TYPE 2 占位检测 | 🔸 部分可用 | 含 `rb`（距离单元号）、`pwr_db_raw`（原始能量）、`pwr_db_rgc`（距离补偿能量）、超阈邻域数；但每次只报一个距离单元 |

`0x3C` 在 V1.0 与 V1.4 两份协议文档中**均无定义**，只能靠抓包确认其返回内容。

## 三、人存版 vs BSD 版：硬件差异还是固件差异

### 3.1 结论：两者都有，主体是固件

**同一颗 SOC。** 两者都是隔空科技 AT6010 60GHz 雷达 SOC，协议同源
——V1.4 是 V1.0 的超集（V1.1 加 TYPE 6 简短呼吸心率，V1.2 加 TYPE 7 BSD 信息）。

**决定性证据：** 人存的资料包 `MS60-1211S80M4-人存(1).rar` 内打包的正是
**V1.0 协议 + 人存手册**，说明手上模块出厂烧录的是人存算法。

### 3.2 规格对比

| 参数 | 人存（现有） | BSD |
|---|---|---|
| 核心 SOC | AT6010 60GHz | AT6010 60GHz |
| 工作频段 | 59~64 GHz | 59~64 GHz |
| 发射功率 | 11 dBm | 11 dBm |
| 水平/俯仰视角 | ±60° | ±60° |
| 封装/引脚 | 12.0×11.0×2.0 mm，双排 1×3 | 12.0×11.0×2.0 mm，双排 1×3 |
| 供电 | 3.0~5.5 V，80 mA | 3.0~5.5 V，80 mA |
| **带宽** | **5 GHz（可调）** | **2 GHz（可调）** |
| 探测距离 | ≤10 m | 汽车 0.5~40 m / 行人 0.5~15 m |
| 灵敏度档位 | 0~10 档 | 0~50 档 |
| 测速范围 | 无（协议标注"预留"） | 6~90 km/h |
| 刷新时间 | — | 100 ms |
| **建立探测时间** | — | **5 s** |

### 3.3 算法差异（主要区别）

| | 人存 | BSD |
|---|---|---|
| 数据命令 | TYPE 0（单目标） | TYPE 7（最多 8 目标） |
| 距离字段 | `u16`，单位 **mm** | `s8`，单位 **米** |
| 速度 | 无 | `s8`，单位 m/s |
| 呼吸检测 | 有 | 无 |

TYPE 7 结构（V1.4 文档 §3.4.8）：

```c
typedef struct {
    s8 range_val;   /* 距离，单位：m */
    s8 angle_val;   /* 角度，单位：度 */
    s8 velo_val;    /* 速度，单位：m/s */
    s8 objId;
} bsd_obj_info_t;

typedef struct {
    u16 obj_num;        /* 最大 8 */
    u16 reserved;
    bsd_obj_info_t obj[8];
} bsd_det_info_t;
```

### 3.4 BSD 对防撞场景未必更优

1. **测速下限 6 km/h**（≈1.67 m/s）。农机作业速度慢、行人移动慢，可能低于下限。
2. **建立探测时间 5 s**。对主动安全预警过慢。
3. **测距分辨率由 3.0 cm 退化为 7.5 cm**，且 TYPE 7 距离字段只有 1 米粒度。
4. BSD 的优势仅两项：**多目标**与**真实速度**。

### 3.5 一处未解决的矛盾（需向厂家确认）

BSD 手册封面内部型号：

```
MS24-1515D12M4-3V3-G-5D-NLS-1T1R
```

结尾 `1T1R`，与人存手册正文"基于 **1T2R**"矛盾。
但该内部型号前缀 `MS24` 按厂家命名规则应为 24GHz，与本产品 60GHz 不符；
尺寸段 `1515` 也与正文 `12×11mm` 不符。且该手册标注"预发版本"。

**结论：这份手册自身型号信息自相矛盾，很可能套用了其他产品模板，
`1T1R` 不能作为结论，必须向厂家确认。**

### 3.6 型号命名规则（已解出）

规则：`MS XX - XXXX X XXX X`

| 段 | 含义 | 取值 |
|---|---|---|
| MS | 品牌 | 觅感 |
| XX | 频段 | 58 / 10 / 24 / 60 |
| XXXX | 尺寸 (LL*WW) | mm |
| X | 接口 | D 直插 / S 邮票半孔 / J 贴片插座 / F FPC |
| XXX | 芯片功耗 | 例：68U / 9M / 12M / 14M / 20M / 26M |
| X | 层数 | 无（两层板）/ 4（四层板） |

据此拆解现有模块 `MS60-1211S80M4`：

```
MS   = 觅感
60   = 60 GHz
1211 = 尺寸 12×11 mm
S    = 邮票半孔接口
80M  = 功耗 80 mA
4    = 四层板
```

**注意：命名规则中不包含"算法类型"或"天线配置"，**
因此仅凭型号无法区分人存版与 BSD 版，这也是厂家需要加 `-BSD` 后缀的原因。

### 3.7 能否自行刷 BSD 固件

协议中存在固件下载命令组（`0x20` 复位 → `0x21` 准备 → `0x22` 擦除 →
`0x23` 烧写 → `0x24` 分包 → `0x25` 结束 → `0x26` 校验 → `0x27` 运行），
说明 SOC 固件可经 UART 更新。

**但必须由厂家提供对应固件镜像，不可自行尝试——刷错镜像有变砖风险。**

## 四、选型建议

### 4.1 选型第一原则

> **必须选择有公开、完整串口协议文档的模块。**

AT6010 的协议不公开，导致前期必须通过反汇编上位机 DLL 才能通信。
下一款模块不应重蹈覆辙——这一条比任何参数都重要。

### 4.2 需求规格

| 需求 | 指标 | 依据 |
|---|---|---|
| 多目标 | ≥3 | 果园同时存在树干、人、农机 |
| 速度输出 | 必需 | 计算 TTC 的前提 |
| 测距范围 | 0.2~15 m | 预警窗口 |
| 测距误差 | ≤10 cm | 预警距离计算 |
| 测角范围 | 水平 ≥90° | 路径内/外判断 |
| 刷新率 | ≥10 Hz | 实时预警 |
| 建立时间 | <1 s | BSD 的 5 s 不可接受 |
| 最低可测速度 | ≤0.3 m/s | 农机与行人速度低 |
| 接口 | UART | ESP32-S3 接入 |
| 协议 | **公开文档** | 第一原则 |
| 环境 | 抗植被摆动、抗粉尘 | 果园场景 |

### 4.4 关键权衡

**LD2450 赢在精度与生态**：±5 cm 测距、±3° 测角、ESP32 例程丰富、更便宜。
**LD6004 赢在天线**：2T2R 角分辨率约为 1T2R 的两倍（~29° vs ~57°），
输出 x/y/z 三维坐标，且提供官方串口协议 PDF 与 GUI 工具；
但**测距精度仅 0.4 m**，是它的主要短板。

**在约 ¥50 价位，角分辨率的上限就是 2T2R ≈ 29°**，这是物理与成本决定的，
想做到 13°（3T3R）或 10°（3T4R）必须上 ¥200+ 档位。

### 4.5 推荐方案：用摄像头补角度，不为雷达堆钱

**核心判断：角度分辨率交给摄像头，不要指望雷达。**

项目本身走的是多模态融合路线，且已规划视觉模型部署，因此应让各传感器各司其职：

| 传感器 | 负责 | 不负责 |
|---|---|---|
| 雷达 | 距离、速度、全天候目标存在性 | 精确角度 |
| 摄像头（OV2640） | 角度、目标类别、方向 | 精确距离、暗光/粉尘 |
| IMU（BMI270） | 自身姿态、运动补偿 | — |

摄像头的角分辨率天然远高于任何毫米波雷达，且硬件已具备。
雷达的角分辨率短板由摄像头弥补——这既是性价比最高的方案，
也是多模态融合设计的核心价值，适合作为比赛的技术亮点陈述。

**具体采购建议**：先买一块 **HLK-LD2450**（几十元）验证
"多目标 + 速度"对预警逻辑的实际提升。
原有的 MS60-1211S80M **保留作兜底与对比**——它的测距精度其实是现有方案里最好的。

若需对比 2T2R 方案，可加购 LD6004（≈¥52），两者合计不足 ¥100。

### 4.6 时间风险提示

距比赛（11 月 18 日）约 7 周。更换雷达平台涉及：
协议验证 → 驱动开发 → 参数整定 → 融合联调。

- **决定更换就应立即下单**，先做协议验证
- **现有模块不要丢弃**，作为保底方案
- **建议购买 2 个**，赛前留有备件
