# 调试日志

> 记录日期：2026-10-02
> 项目：智行护航（果园小型农机防撞头盔，ESP32-S3 + 雷达 + IMU + 摄像头）

本文按时间顺序记录项目开发中的关键调试过程、根因和结论，供后续排错与复盘。

---

## 一、雷达（MS60-1211S80M）

### 1. 串口无应答（反复出现）

- **现象**：发命令收不到回复，被动监听 0 字节。
- **根因**：模块是**从机**，不主动发数据；且最早固件发的 `0xFE`（读版本）命令**模块根本不支持**（协议文档里没有这条）。
- **结论**：无应答 ≠ 接线坏。数据靠 `0x30` 命令主动轮询获取。

### 2. OUT 引脚读不到东西

- **现象**：OUT 脚一直高电平，装 GPIO 中断也抓不到变化。
- **根因**：OUT 只是 **1-bit 存在信号**（有人高/无人低，或 PWM），不含距离/角度数据。
- **结论**：数据只能走 UART，别在 OUT 上浪费时间。

### 3. 协议逆向

- 从官方上位机 `ATRadarSettingTool` 的 `airhost.dll` 反汇编出完整命令表。
- 确认帧格式 `0x58 命令 / 0x59 回复 / 0x5A 上报`，校验和规则。
- 输出：`Technical Support Document/雷达AT6010_命令表(从上位机airhost.dll提取).md`

### 4. 精度归因

- 结论：精度瓶颈在**模块内部算法 + 物理 + 参数**，不在协议解析（逐字节已核对）。
- 改进方向：用 `rb_conf`/`angle_conf` 过滤低置信度帧；调检测窗口与灵敏度。

## 二、IMU（HW-991 / BMI270）

- **现象**：读不到有效数据。
- **根因**：BMI270 上电后必须**先上传 8192 字节官方配置块**才会输出。
- **解决**：`imu-debug` 工程已跑通（见 `imu-debug/components/imu_bmi270/`）。

## 三、摄像头（OV2640）

### 1. 每帧只收 1/8 数据

- **现象**：ESP-IDF 下日志刷 `E:RX:115200-14400`（应收 115200 字节，实收 14400）。
- **排查**：逐项排除引脚映射（与 ESP32-S3-EYE 完全一致）、XCLK（16→20MHz）、格式配置。
- **根因**：esp_video 的 DVP 驱动在 **RGB565（非 JPEG）模式下对帧大小做严格匹配**，1/8 帧就报错。
- **解决**：摄像头输出改 **JPEG 格式**（帧大小可变，走不校验大小的路径），流水线加 JPEG 解码节点。

### 2. 写格式寄存器 I2C 超时

- **现象**：换 JPEG/大分辨率格式后报 `I2C bus is still busy but software timeout`。
- **根因**：SCCB 用 **400kHz** 太激进，大批量写寄存器挂总线。
- **解决**：SCCB 降到 **100kHz**（与 Arduino esp32-camera 一致）。

### 3. 硬件隔离验证

- 用 Arduino CameraWebServer（PlatformIO 编译）确认**摄像头硬件本身是好的**。
- 结论：问题全部在 ESP-IDF 的 esp_video 驱动配置，不是硬件。

## 四、行人检测（ESP-WHO）

- 工程：`vision-debug/esp-who/examples/object_detect`，模型 `pedestrian_detect`。
- 摄像头改成 JPEG + 解码节点后，检测出框（置信度 0.72~0.84）。
- 后续加了 Web 推流（`/stream` MJPEG + `/boxes` JSON + 前端画框）。

## 五、开发环境与 MCP

关键结论见 `开发环境与MCP配置说明.md`，要点：

- **Codex 沙箱会虚拟化注册表**：沙箱内读环境变量/PATH 会看到假值，必须以非沙箱方式读。
- **环境变量在进程创建时固定**：写入后要重启 Codex 才生效。
- **沙箱 ACL 让 `.git` 卡死整个沙箱**：`.git` 所有者被沙箱账户占用，改回真实用户即修复。

---

## 六、雷达选型结论

- 速度是第一性需求，现有模块无速度 → 速度由摄像头+IMU 提供。
- BSD 版排除（测速下限 6km/h、建立时间 5s、距离 1m 粒度）。
- 低价位候选：HLK-LD2450 / LD6004。详见 `雷达选型与精度分析.md`。
